# 本地预览

顶栏「本地预览」启动的是当前博客自己的开发服务器。编辑器里的「预览」只渲染 Markdown，不会执行 Astro、MDX 或项目脚本。两者不要混用。

## 启动和停止

1. 先选择博客目录。
2. 打开「本地预览」，可先点「检查环境」。检查 Node.js、`npm.cmd`、`package.json` 的 `dev` 脚本，以及 `node_modules/astro`。
3. 「启动本地预览」在该博客目录执行真实的 `npm run dev`，项目里的 predev 会照常运行。客户端不安装依赖，也不改博客配置或脚本。
4. 状态变为「运行中」表示日志里的本地地址已经能访问，不是进程刚创建成功。地址来自本次输出，不假定端口 4321。
5. 「在浏览器打开」只打开已验证的 `http://127.0.0.1` 或 `http://localhost` 地址。「停止预览」只结束这次启动的进程树。

环境缺失、没有 dev 脚本、依赖缺失、脚本失败、启动超时或进程退出时，面板显示原因。修正后可以重新启动。

自动检测使用系统 PATH，并读取 Windows 用户和系统的 Path，以覆盖从桌面启动时 PATH 比终端更短的情况。不会把 Electron 自己的 Node 算作已安装。需要指定安装位置时，用「选择 Node 和 npm」分别选择 `node.exe` 和同目录体系中的 `npm.cmd`；两者都必须能返回版本号才会保存。「恢复自动检测」清除这项设置。

## 在站点中预览当前文章

编辑器工具栏的「在站点中预览」打开当前文章在本地站点中的地址，前提是预览已经处于运行中。

- 普通文章读取项目 `yukina.config.ts` 里唯一的 `slugMode`：`RAW`、`HASH` 或 `PINYIN`，再按博客现有规则生成 `/post/...`。
- `PINYIN` 使用该博客已安装的 `pinyin-pro`。缺少该依赖或 slug 规则无法确定时，不会编造地址，可以选择打开站点首页。
- 已有 AI 日报打开 `/ai-daily#daily-...`，没有单独的日报编辑流程。
- 站点读取磁盘上的文件。有未保存修改时，需要先保存或放弃。保存失败或发生冲突时不会打开，也不能把未保存内容说成已经预览。

## 不会做的事

- 不结束占用端口的其他程序，也不按进程名结束 Node。端口被占用时，显示项目实际换到的地址，或脚本自己的失败原因。
- 不监听 `0.0.0.0`，不追加对外网开放的参数。
- 不执行日志里的链接或命令。日志有长度上限，会去掉 ANSI 控制符，并隐藏 npm 令牌。
- 不在原始博客上自动运行可能写文件的 predev。开发验收使用隔离副本。
