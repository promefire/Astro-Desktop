# 文章编辑与恢复

点击文章后，主工作区有两种编辑模式，操作同一份正文缓冲区：

- **编辑模式**：MarkText Muya 内核（@muyajs/core 0.2.0）所见即所得。底部状态为「Muya 所见即所得编辑器」。
- **源码模式**：CodeMirror 6 直接编辑 Markdown 正文。编辑区标明「Markdown 正文源码」，底部状态为「Markdown 源码编辑器」。

`.md` 默认打开编辑模式。工具栏用 `role="tablist"` / `role="tab"` / `aria-selected` 切换，方向键、Home 和 End 可以移动焦点。处理图片、保存或尚未处理恢复记录时，切换按钮禁用。本阶段没有独立预览、左右分栏或三栏。

正文、草稿和已有 AI 日报共享这套编辑器。草稿来自 `src/contents/drafts`，保存不会把它移动到正文目录。日报仍无新建入口或专属编辑表单。

工具栏保留撤销、重做、插入图片、外部编辑器、站点预览、重新加载和导出副本。撤销和重做只作用于当前可见的编辑器。

## 统一正文与模式切换

```text
文章原始源码
├── 原始 Frontmatter
└── Markdown 正文缓冲区
    ├── 编辑模式（Muya）
    └── 源码模式（CodeMirror 6）
```

`splitMarkdownSource` 按 frontmatter 边界切开源码。BOM 和完整 frontmatter 块按字节保留，包括注释、字段顺序、未知字段和原来的换行。源码模式只编辑正文，不把 Frontmatter 放进编辑区，避免误改 YAML。右侧属性栏继续显示已保存版本的 Frontmatter。

从编辑模式切到源码模式时，读取 Muya 当前 Markdown，写入统一缓冲区，再载入 CodeMirror。从源码模式切回时，读取 CodeMirror 的正文，写入同一缓冲区，再交给 Muya。Muya 渲染完成前不继续编辑。切换不写磁盘，不清除未保存状态，也不另写一条恢复记录。

送入 Muya 的正文先把 CRLF 转为 LF，这个转换不会在打开文章时写回文件。只比较换行符时视为相同；其他空白仍算修改。若 Muya 规范化了正文，以它实际返回的 Markdown 作为当前正文，并且只在内容确实变化时标记未保存。

两种模式各自保留撤销历史。模式切换本身不是撤销步骤。文本确实变化时，进入该模式会替换该侧文档，因此这一侧的撤销历史会清空：Muya 的 `setContent` 会清除自己的历史，CodeMirror 用新的 `EditorState` 替换。文本相同则不替换，该侧历史保留。工具栏撤销、重做作用于当前可见编辑器。切换文章或组件卸载后，旧文章的异步回调不再写入新文章。

编辑模式插入图片会通过 `setContent` 追加，因此会清空 Muya 这一侧的撤销历史。源码模式在光标处插入，保留 CodeMirror 自己的撤销历史。

## Frontmatter 与正文分离

两种模式都不解析、不编辑 frontmatter。保存内容是原始 frontmatter 加上当前统一正文。这样保留 frontmatter 原文的精确格式（缩进、注释、自定义字段、BOM 和换行）。

进入编辑模式后，Muya 会规范化 Markdown 正文（空格、空行、列表标记等可能改变），保存后与手动逐字节编辑源码不完全一致。如果文章没有 frontmatter，整个源作为正文加载；保存时也不添加 frontmatter。未闭合的 frontmatter 不切出正文，避免把残缺 YAML 当成可编辑正文。

## 保存流程

1. 请求绑定活动项目、文章相对路径及打开时的 SHA-256 revision。拒绝集合外路径、目录链接、硬链接文章和超过 4 MB 的源码。
2. 先把编辑内容写入客户端恢复记录，再核对磁盘版本和 frontmatter。字段无效或版本不同则停止，编辑器保留输入。
3. 在文章同目录独占创建临时文件，完整写入并同步；把旧源码备份到客户端数据目录。
4. 再次检查路径和版本，替换原文件。成功后更新已保存属性并清理编辑恢复记录；清理失败单独提示，不把已完成的保存报告为失败。

不重新生成整份 YAML。保存使用切出的原始 frontmatter 原文加上当前正文缓冲区。文件校验与最终 rename 之间仍存在操作系统级竞态窗口，不宣称对其他进程提供文件事务或阻止恶意竞态。备份和恢复记录未加密，属于本机用户数据；当前没有备份保留期限或自动清理功能。不要将客户端数据目录提交到博客仓库。

保存成功后更新基准 revision 和已保存状态，并把保存后的正文同步到当前模式。不改变正在使用的模式，也不为了同步而重建 Muya。恢复记录、放弃修改、重新加载磁盘版本和外部编辑器重新加载，都写回同一正文缓冲区，并在当前模式显示。

## 粘贴与图片

两种模式共用同一套图片服务。图片转换为 WebP（质量 80）。启用 S3/R2 时插入上传后的公开链接；未启用时插入文章同名图片目录的相对链接。上传或转换失败不插入伪链接。处理过程中禁止切换模式。返回时会确认仍是同一篇文章，避免写入另一篇或在错误位置插入。

编辑模式保留 Muya 的选择、拖拽和剪贴板图片处理。图片文件和远程图片 Markdown 在捕获阶段拦截，避免与 Muya 默认粘贴重复执行。源码模式把生成的 Markdown 图片引用插在当前光标处。

粘贴文本时：

- 含有图片文件（例如从文件资源管理器复制的图片、截图）→ 走 `importImage`，转 WebP 并存储，再插入生成的 Markdown 图片引用。
- 含有远程 Markdown 图片链接（`![...](https://...)`，包括从语雀复制的链接）→ 下载、转换、压缩后上传或保存到本地，并替换成功的链接。失败的链接保留原文。同一次粘贴里的同一地址只处理一次。
- 其他文本（纯文本、HTML、本地图片、代码块等）→ 交给当前编辑器的默认粘贴，不再额外拦截。

这一逻辑用 `clipboard.files` 优先判断，`clipboard.text` 只在前者无内容时查看。Muya 默认粘贴会规范化 Markdown；自定义粘贴只处理图片与远程链接。

## 冲突与未保存内容

离开文章、切换页面 / 项目、刷新或关闭窗口时，如果存在修改，会提示取消、放弃修改或保存并继续。保存失败留在编辑器，不继续导航。恢复记录在停止输入 600 ms 后写入，不会自动保存到文章文件；最后一次记录尚未完成时发生进程崩溃或断电，不能保证恢复全部最后输入。

外部修改导致冲突时，可先「另存编辑副本」，或「重新加载磁盘版本」。重新加载先保留当前编辑的恢复记录，之后从顶部「恢复记录」取回或导出。每个项目的每篇文章只有一份当前编辑恢复记录，后续编辑会更新它；需要长期保留不同版本时应先导出副本。

重新打开文章时发现未保存记录，会先让用户选择恢复或放弃。恢复时保留原 baseRevision，磁盘已改变时仍会停止覆盖。即使原文件被删除或移动，也能从顶部恢复列表查看、导出记录。恢复副本不覆盖已有目标，需另选名称；创建副本需要支持硬链接的文件系统（本机 NTFS 已验证）。

记录位置：Electron `userData/editor/recovery/`；旧源码备份：`userData/editor/backups/`。文件名由项目与文章路径哈希组成。损坏恢复记录会提示且不静默覆盖，需要先保留该文件并人工修复或移出此目录。旧源码备份暂未提供历史版本管理界面。

## MDX 仅源码模式

`.mdx` 默认进入源码模式。「编辑模式」保持禁用，并显示「MDX 包含可执行语法，仅支持源码编辑」。内容不会交给 Muya，也不会在客户端执行 import、组件或表达式。保存仍经过现有的版本检查、备份和原子替换。

## 源码模式编辑器

源码模式使用 CodeMirror 6（`@codemirror/view` 6.43.14、`@codemirror/state` 6.7.6、`@codemirror/commands` 6.11.1、`@codemirror/lang-markdown` 6.5.2、`@codemirror/language` 6.13.1、`@codemirror/search` 6.7.2、`@lezer/highlight` 1.2.5）。提供 Markdown 语法高亮、行号、当前行、自动换行、撤销重做、查找替换、两个空格的 Tab 缩进、Ctrl+S / Cmd+S、中文输入、浅色和深色主题。编辑区的可访问名称是「Markdown 正文源码」。

CodeMirror 不直接写文件。隐藏的编辑区保持布局以便测量，但不可交互；同一篇文章同时只有一个 Muya 实例和一个 CodeMirror 实例。React 开发模式的重复挂载会先销毁上一个实例。

## 已知限制

- 没有独立预览、左右分栏或三栏。站点效果仍用本地预览。
- 两种模式都不能改 Frontmatter。属性栏是已保存版本。
- 编辑模式的图片插入会清空该侧撤销历史。模式切换在正文变化时也会清空被替换那一侧的历史。
- 编辑模式直接显示 `http` 和 `https` 图片，不改写正文里的链接。脚本和网络请求仍然只允许本机来源。
- 相对路径的本地图片仍由 Muya 按页面地址加载。找不到文件时图片块显示失败状态，Markdown 引用留在正文里，不会换成伪链接。
- 恢复记录仍有约 600 ms 的写入间隔，崩溃前最后一次输入不保证已经写入。

## 外部编辑器

打开当前文章时使用 Windows 已经为该扩展名设置的默认程序，不需要在客户端里再选一次编辑器。`.md` 和 `.mdx` 各自使用自己的默认方式。项目设置里的「检查默认程序」只查询系统登记，不会启动程序，也不会显示模拟的打开成功。

编辑器工具栏的「外部编辑器」打开磁盘上的当前文章：

- 该扩展名还没有默认程序，或系统拒绝打开时，编辑区保持原样，并显示失败原因。
- 编辑区有未保存修改时，必须先取消、放弃修改或保存。取消不会打开外部程序，也不会清空编辑区。
- 磁盘版本已经变化时，先选择取消或重新加载。重新加载后才会打开。
- 文章路径交给系统默认方式处理，不经过命令行拼接，因此空格、中文和 `&` 会保留。
- 打开成功后，编辑区换成「正在使用外部编辑器」引导，编辑区与工具栏都不可用。保存和 Ctrl+S 也不会写回磁盘。

外部程序保存后，编辑区不会自动变化。在引导页点击「重新加载」才会读回磁盘并恢复编辑。若重新加载之后磁盘又被其他程序修改，再次保存仍会因 revision 不一致而停止覆盖。客户端不会结束已经启动的外部程序，也还没有自动监听文件变化。若要更换程序，请在 Windows 的默认应用里修改 `.md` 或 `.mdx` 的打开方式。

## 预览边界

编辑器的「在站点中预览」使用已启动的本地 Astro 站点，见 [PREVIEW.md](PREVIEW.md)。编辑器本身不再提供内置 Markdown 预览窗格。站点预览打开的是磁盘上的文章，不是编辑区里尚未保存的内容，需要先保存或放弃修改。
