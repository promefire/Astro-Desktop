# 源码编辑与恢复

点击文章后，主工作区提供源码、预览、左右分栏三个视图。分栏中间拖动可调整宽度，也支持聚焦分隔条后按左右方向键。切换视图保留当前内容和编辑器状态。右侧属性显示已保存版本；目前直接在源码中修改 Frontmatter，没有可视化属性表单。

CodeMirror 提供 Markdown / YAML 高亮、行号、折叠、查找替换、撤销重做。保存按钮或 Ctrl+S 将修改写入当前文章。普通文章和已有 AI 日报共享编辑器，日报仍无新建入口或专属编辑表单。

## 保存流程

1. 请求绑定活动项目、文章相对路径及打开时的 SHA-256 revision。拒绝集合外路径、目录链接、硬链接文章和超过 4 MB 的源码。
2. 先把编辑内容写入客户端恢复记录，再核对磁盘版本和 Frontmatter。字段无效或版本不同则停止，编辑器保留输入。
3. 在文章同目录独占创建临时文件，完整写入并同步；把旧源码备份到客户端数据目录。
4. 再次检查路径和版本，替换原文件。成功后更新已保存属性并清理编辑恢复记录；清理失败单独提示，不把已完成的保存报告为失败。

不重新生成整份 YAML。编辑器维护原始文本与 CodeMirror 坐标的映射，保留未修改部分的 BOM、CRLF / LF / 混合换行、注释、自定义字段、MDX 内容；新增换行沿用源文件第一个换行符。撤销重做也恢复原始文本。

文件校验与最终 rename 之间仍存在操作系统级竞态窗口，不宣称对其他进程提供文件事务或阻止恶意竞态。备份和恢复记录未加密，属于本机用户数据；当前没有备份保留期限或自动清理功能。不要将客户端数据目录提交到博客仓库。

## 冲突与未保存内容

离开文章、切换页面 / 项目、刷新或关闭窗口时，如果存在修改，会提示取消、放弃修改或保存并继续。保存失败留在编辑器，不继续导航。恢复记录在停止输入 600 ms 后写入，不会自动保存到文章文件；最后一次记录尚未完成时发生进程崩溃或断电，不能保证恢复全部最后输入。

外部修改导致冲突时，可先「另存编辑副本」，或「重新加载磁盘版本」。重新加载先保留当前编辑的恢复记录，之后从顶部「恢复记录」取回或导出。每个项目的每篇文章只有一份当前编辑恢复记录，后续编辑会更新它；需要长期保留不同版本时应先导出副本。

重新打开文章时发现未保存记录，会先让用户选择恢复或放弃。恢复时保留原 baseRevision，磁盘已改变时仍会停止覆盖。即使原文件被删除或移动，也能从顶部恢复列表查看、导出记录。恢复副本不覆盖已有目标，需另选名称；创建副本需要支持硬链接的文件系统（本机 NTFS 已验证）。

记录位置：Electron `userData/editor/recovery/`；旧源码备份：`userData/editor/backups/`。文件名由项目与文章路径哈希组成。损坏恢复记录会提示且不静默覆盖，需要先保留该文件并人工修复或移出此目录。旧源码备份暂未提供历史版本管理界面。

## 预览边界

预览只渲染 Markdown / GFM，不执行原始 HTML、脚本、MDX 组件、import 或表达式；图片显示说明文本，链接显示文字，不请求外部资源。布局、组件与图片的完整效果由后续真实 Astro 本地预览提供。

实现参考 HexoHub 研究快照 `bb39de8` 的主区编辑器模式和分栏交互，保留独立实现。YAML 区域使用 CodeMirror 官方 [yamlFrontmatter](https://code.haverbeke.berlin/codemirror/lang-yaml)，正文使用 Markdown 语言支持；不会将语法解析当成执行文章代码。
